# 雾隐镇

以「声证」为特色的 9 人中文语音狼人杀：实时原声圆桌、私人证据标记、可回听片段，以及引用真实票型和死亡事件的赛后复盘。规则由服务端确定性引擎执行，字幕和主持音只使用灵汐 API。

当前版本已接通多人房间、完整对局、WebRTC、SQLite 恢复和响应式界面，是可本地运行的单实例工程。所有功能经 PR 迭代；CI 包含逐文件覆盖门禁、真实 Chrome 九客户端验收和容器启动检查。真实灵汐调用、公网 TURN 和真人试玩仍有明确的验收边界，见文末。

## 快速开始

要求 Node.js 24.x，CI 与容器固定使用 24.15.0。生产代码使用 Node 内置能力；Playwright 仅为开发依赖。

```bash
npm ci
npm start
```

打开 <http://127.0.0.1:4173>，创建房间并分享房间码。九名玩家各自打开一个浏览器标签页，加入、准备后由房主开局。座位保存在各标签页的 `sessionStorage`；刷新可恢复本人席位。

未配置密钥也能进行规则对局、实时原声和片段回听；灵汐字幕与主持音会明确显示不可用。配置参考 [.env.example](.env.example)，应用不会自动读取 `.env`，本地可使用 Node 的环境文件支持：

```bash
node --env-file=.env -e "require('./server').start()"
```

只在本地未跟踪的环境文件中配置 `LINGXI_API_KEY`。默认上游固定为 `https://api.aicso.top`，不向浏览器下发该密钥。Docker 运行：

```bash
docker compose config --quiet
docker compose up --build -d
```

容器默认只发布到宿主机 `127.0.0.1:4173`，数据保存在命名卷。远程真人使用须配置 HTTPS；复杂 NAT 网络须配置自己的 STUN/TURN。配置、备份、恢复和升级见 [运行手册](docs/OPERATIONS.md)。

## 产品分析

目标用户是熟人组局和偏好逻辑推理的中文语音玩家。产品假设是：比起堆叠角色，清晰的顺序发言和有依据的复盘更能改善一局游戏的质量。组局一分钟、局长 25–40 分钟是体验目标，尚无真人研究数据证明。

| 参考对象 | 借鉴方向 | 本项目的选择 |
| --- | --- | --- |
| [百变大侦探](https://mszmapp.com) | 角色沉浸、语音互动、搜证和投票闭环 | 聚焦一局狼人杀与声证，不引入剧本商城和社区广场 |
| [Nightfall](https://github.com/the-nightforge/Nightfall) | 规则引擎、玩家级状态与重连的架构思想 | 原创实现，不复制缺少仓库级许可证的源码，不接入其语音供应商 |
| [AI Werewolf](https://github.com/xiaoxiaomugong/AI-Werewolf-Live-Voice-Game) | 实时语音交互的技术探索 | 真人博弈，AI 只提供表达能力，不决定行动或胜负 |

上述内容是公开页面参考与产品判断，不宣称竞品没有类似能力。原调研日期为 2026-10-23；当前产品说明和素材来源见 [产品文档](docs/PRODUCT.md)。

### 特色：声音成为可核对的证据

| 能力 | 实际行为 | 公平与隐私边界 |
| --- | --- | --- |
| 实时原声圆桌 | 当前发言者向最多八名接收者发送 WebRTC 音轨 | 玩家主动开启；换人时停止旧麦克风；只转发鉴权信令 |
| 声证片段 | 真实录音绑定局号、阶段、席位和 SHA-256，播放前校验 | 摘要只证明字节一致，不证明说话内容或现实身份 |
| 私人标记 | 玩家标记自己有权查看的真实片段 | 只属于创建者，不作为系统判定 |
| 事实复盘 | 展示身份、票型、死亡和保留声证，转折引用可解析的记录 | 不调用 LLM 编造评价；局中不公开完整身份 |
| 原声留存 | 默认临时处理，显式勾选才持久化并进入赛后回听 | 默认两小时 TTL，可删除自己的片段，不永久归档 |

## 产品设计

```text
创建 / 加入 -> 九席准备 -> 私密发身份 -> 夜间角色行动
                                           |
                          白天顺序发言 <----+
                                |
                          公投 -> 遗言 -> 猎人处理
                                           |
                           未结束：下一夜 / 已结束：声证复盘 -> 再来一局
```

### 固定九人标准局

| 角色 | 数量 | 核心规则 |
| --- | ---: | --- |
| 狼人 | 3 | 每晚选择目标，严格多数形成狼刀 |
| 预言家 | 1 | 每晚查验一名其他存活玩家的阵营 |
| 女巫 | 1 | 解药、毒药各一瓶，同夜最多使用一种 |
| 猎人 | 1 | 被狼袭或放逐可以开枪；被毒杀不能开枪 |
| 平民 | 3 | 发言和投票 |

好人清除全部狼人获胜；狼人数量达到或超过其余存活玩家时获胜。平票不放逐；放逐后先遗言，再处理合法猎人行动，最后判定胜负。精确边界、超时规则和事件语义见 [权威规则](docs/RULESET_STANDARD_9_V1.md)。

### 界面与操作

- 大厅：昵称、建房、房间码加入、准备、房主开局。
- 圆桌：在线与存活席位、当前发言者、绝对截止时间、角色行动与确认态。
- 语音区：主动启用实时麦、录制片段、上传状态、灵汐字幕、AI 主持音、留存选择。
- 证据与复盘：鉴权回听、私人标记、原声摘要、票型和死亡引用、再来一局。
- 治理：房间内举报提交到当前房主视图，不向外部平台发送，也不自动惩罚玩家。

桌面采用圆桌与个人情报分区，移动端顺序排列，主操作不依赖悬停。规则弹窗支持键盘；断线、版本冲突、麦克风拒绝、转写失败均有反馈。客户端不生成演示身份或模拟字幕来填补服务失败。

### 语音失败与权限

灵汐使用 `gpt-4o-transcribe` 转写和 `gpt-4o-mini-tts` 主持音，网关设有固定模型、输入限制、并发/速率上限、超时和错误脱敏。`configured`、`implemented`、`checked`、`healthy` 分开报告，配置了密钥不等于真实调用通过。

原声与语音智能相互独立：灵汐失败仍可回听真实录音，主持音失败展示同内容文字，阶段计时继续。WebRTC 不通可改用片段；它是浏览器原生媒体传输，不接入第二家商业语音智能 API。当前未实现灵汐 AI Realtime、AI 补位或自动判断发言真假。

## 项目架构

```text
Chrome 响应式客户端
  |-- 同源 HTTP / JSON / 带 Bearer 的 SSE --> Node.js 24 模块化单体
  |                                           |-- Room 与确定性 Game 引擎
  |                                           |-- 按玩家裁剪的 Snapshot
  |                                           |-- SQLite 原子快照、事件与幂等
  |                                           |-- 声证引用 / 私人标记 / 事实复盘
  |                                           |-- 本地授权媒体文件（两小时 TTL）
  |                                           +-- 灵汐 STT / TTS 网关
  |
  +-- WebRTC P2P 原声 --> 当前房间其他浏览器
       同源服务转发信令；可选自管 TURN，不是 SFU
```

| 模块 | 职责与关键约束 |
| --- | --- |
| `src/game`、`src/store` | 确定性事件、重放、原子追加；按牌局/玩家隔离幂等键 |
| `src/projection` | 嵌套白名单，只公开本人有权看到的内容，不暴露内部事件序号 |
| `src/room` | 九席生命周期、安全令牌、准备/开局、计时、房主迁移、重连/重开 |
| `src/http` | 同源检查、JSON/静态资源白名单、SSE 心跳/恢复/背压、健康计数 |
| `src/client`、`src/media` | 可测试客户端、原生录音/播放、鉴权信令、顺序发言的 P2P 音轨 |
| `src/voice`、`src/features` | 灵汐适配、片段配额、授权回听/删除、标记、复盘和举报 |
| `src/persistence` | SQLite schema v1、单写锁、校验与备份恢复、私有媒体文件 |
| `src/runtime.js`、`server.js` | 配置与依赖装配、进程启停和资源释放 |

客户端只提交意图和可见版本，服务端验证身份、阶段、目标和技能；SSE 使用查看者独立的不透明 cursor。角色、查验和夜间行动不依赖前端隐藏。座位令牌不进入 URL；灵汐密钥不进入前端、日志或仓库。

当前选用内置 SQLite，实现单进程持久化与恢复，而非计划早期提出的 PostgreSQL。它减少 Hackathon 的运行依赖，同时保留事务和恢复验证；不支持多实例同时写入。服务重启后座位先标记离线，玩家凭原标签页令牌重连。生产扩容需要重新设计房间所有权与共享媒体，不能只更换数据库连接串。

## 开发与验证

```bash
npm run test:coverage
npx playwright install --with-deps chrome
npm run test:browser
```

截至本轮本地验收：

- `npm run test:coverage`：通过；290 个测试，32 个生产执行文件，行 99.62%、分支 97.67%、函数 99.30%，逐文件三项均不低于 95%。
- `npm run test:browser`：通过；2 个真实 Chrome 验收，涵盖九个独立上下文完整对局、重连、私密信息、键盘、桌面/390px 移动布局、录音上传/回听，以及八接收者原生 WebRTC RTP 与换麦。
- `docker compose config --quiet`：通过。

覆盖率统计包括前后端全部生产 JavaScript，客户端逻辑通过注入依赖、DOM/浏览器边界测试执行；没有冻结的旧代码例外。Chrome 验收另外验证真实浏览器行为，附带主会话字节覆盖样本，不宣称 Chrome 行/函数/分支单独达到 95%。静态 HTML/CSS 通过结构与实际页面验收，不计入 JavaScript 执行覆盖率。

CI 的 `quality`、`browser`、`container` 分别执行全量覆盖与清单核对、Chrome 回归、容器构建启动及健康检查；只使用本地合成音频和假上游，不需要真实玩家数据或计费密钥。报告与截图仅保存到 [本仓库 Actions](https://github.com/1351914167/hackthon/actions)，本地位于忽略的 `coverage/`、`artifacts/`。

## 验收边界

真实灵汐 STT/TTS 尚无有效密钥进行调用验收，当前证据为本地合同、错误和降级测试。实时媒体已验证同机 Chrome 多客户端；公网跨 NAT、真实 TURN、不同设备音质和移动端系统浏览器需要部署环境联调。用户研究、容量压测、账号体系、商业内容审核和多实例高可用不在当前单实例交付范围。

本机 Docker daemon 不可用，因此本地仅完成 Compose 配置检查；容器构建与健康结果以本仓库对应提交的 CI `container` 检查为准。代码、设计、PR 和验收产物只提交到 `1351914167/hackthon`，没有向其他网站发布项目内容。
