## 修复结果

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 放逐遗言没有实现 | 与冻结规则不一致，被放逐者无法完成遗言 | 增加 LAST_WORD、本人结束和超时，再处理猎人与胜负 |
| 中断时新增的轮次校验错误 | ROLE_REVEAL 后第一夜无法开始 | 首夜固定为 round=1；后续夜晚才递增轮次 |

| 部分事件直接写状态 | 损坏记录可能在重放时形成非法局面或原生异常 | 校验阶段、角色、目标、票型、轮次和状态集合，统一领域错误 |
| 使用 JSON 字符串判断对象相等 | 内容相同但字段顺序不同的事件会被错误拒绝 | 使用结构相等比较，增加重排 JSON 字段后的重放测试 |
| 幂等检查只存在于 append | 请求在到达存储前被旧 seq 拒绝 | 提供 findAction，增加认证意图到 decide/append 的编排测试 |
| actionId 未按玩家隔离 | 同局不同玩家的请求可能冲突或拿到他人结果 | 作用域改为 gameId / actorSeatId / actionId，并校验游戏绑定 |
| 克隆失败后留下事件 | 出现事件已追加、幂等记录缺失的部分写入 | 所有可失败克隆在修改存储前完成 |
| 快照暴露全局 seq | 可从序号跳变推断私密行动次数 | 不公开权威 seq；version 只由该查看者可见内容生成 |
| 公共嵌套对象整块复制 | 后续新增内部字段时可能泄露 | 死亡、票型、查验、技能库存逐层白名单，加入嵌套 canary 测试 |
| 快照缺少本人提交结果与遗言操作 | 刷新后无法恢复确认态，被放逐者无操作入口 | currentAction 区分未提交和弃权，死亡判断前处理遗言权限 |

## 测试质量调整

原测试具备较高覆盖率，但部分场景通过直接修改 state 进入目标阶段，不能证明阶段能够串联。本轮保留必要的局部边界测试，并新增：

- 完全通过合法命令生成的好人胜利、狼人胜利和猎人 pending 路径，重放结果与实时状态相等。
- 通过合法夜间、公投和遗言完成对局，再验证结束态身份公开。
- 成功命令重试先命中幂等记录，不再次调用规则决定函数。
- 不同认证玩家复用相同 actionId 时互相隔离。
- 事件或行动不可克隆时，没有部分写入或残留幂等记录。
- 其他玩家连续修改私密行动时，观战者和无关玩家的整个快照及 version 保持不变。
- 嵌套内部字段注入后，所有查看者的序列化响应都不包含 canary。

没有增加测试框架、生产依赖、锁文件或覆盖率排除标记。

## 设计修正

- Room 负责逐人入座、准备、当前房主和重连；`/start` 内原子校验房主与全员准备后才创建 Game 并立即开局。Game 中的 hostSeatId 只是开局发起人，不能当作可迁移的房间权限，也不能预先创建 Game 后再等待已迁移的房主开局。
- 客户端使用 expectedVersion；应用层完成身份、幂等和可见版本校验后才向 decide 注入内部 expectedSeq。
- SSE 使用带 Bearer 的 fetch 流读取和按查看者隔离的 cursor，不能把原始事件或内部序号直接发给浏览器。
- SSE 只在该查看者可见内容变化时推送。固定心跳不携带私密操作次数或时间；哈希版本本身并不能消除错误推送节奏造成的侧信道。
- 根目录执行脚本和未来新增脚本都必须进入最终覆盖清单。Node 未加载的文件不能因为没有出现在报告里就被视为已覆盖；Chrome 人工验收也不能替代执行覆盖率。
- README 同步区分已实现领域模块、运行中的旧原型、未接入房间服务和待确认语音方案；不再承诺本轮 PWA、12 人局或已验证 Realtime。
