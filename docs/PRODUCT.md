# 雾隐镇产品说明

雾隐镇是一款 9 人中文语音狼人杀 Web 游戏。它把实时原声、按段声证和确定性规则放在同一局游戏中：玩家依靠自己的判断完成发言与投票，服务端负责身份权限、阶段推进和胜负结算，灵汐只提供转写与主持音。

本文描述当前可运行产品，不把路线图写成已交付能力，也不声称已经完成用户研究。目标用户和体验判断是 Hackathon 阶段的产品假设，需要通过真实试玩验证。

## 产品边界

当前版本提供：

- 通过房间标识创建或加入 9 人房间。
- 席位准备、房主开局、断线重连和房主迁移。
- `standard-9-v1`：3 狼人、预言家、女巫、猎人和 3 平民。
- 服务端权威的夜间行动、白天发言、公投、遗言、猎人开枪和胜负判定。
- 当前 speaker 的 WebRTC P2P 实时原声。
- 玩家主动录制的原声片段、灵汐转写、私人标记和赛后复盘。
- SQLite 单实例恢复和本地容器运行。

当前版本不提供：

- 匹配大厅、排行榜、付费或复杂社交关系。
- 警长、第三方阵营和扩展角色。
- AI 判定发言真假、AI 代替玩家推理或 AI 修改胜负。
- 多实例房间调度、共享媒体存储或 PostgreSQL 部署。
- 内置 TURN 服务或公网媒体可用性保证。

## 核心体验

```text
创建 / 加入房间
  -> 9 席准备
  -> 服务端发放私密身份
  -> 夜间角色行动
  -> 白天实时原声发言与声证片段
  -> 公投 / 遗言 / 猎人结算
  -> 服务端判定胜负
  -> 可验证事实复盘
  -> 再来一局
```

客户端只提交意图。身份、存活状态、当前 speaker、技能结果、票型和胜负均来自当前玩家的服务端白名单快照。浏览器不会在本地推进牌局，也不会用假身份或假转写补齐服务不可用状态。

## 9 人规则

| 阵营 | 角色 | 数量 | 当前规则 |
| --- | --- | ---: | --- |
| 狼人 | 狼人 | 3 | 每晚各自选择目标；严格多数形成狼刀。 |
| 好人 | 预言家 | 1 | 每晚查验一名其他存活玩家的阵营。 |
| 好人 | 女巫 | 1 | 解药、毒药各一瓶，同夜只能使用一种。 |
| 好人 | 猎人 | 1 | 被狼袭或放逐时可开枪；被毒杀不能开枪。 |
| 好人 | 平民 | 3 | 通过发言、票型和公开事件找出狼人。 |

好人放逐全部狼人获胜；狼人数量达到或超过其他存活玩家时获胜。白天唯一最高票玩家被放逐，平票不进入二次 PK。放逐玩家先发表遗言；若其为可开枪猎人，遗言后处理猎人行动，再判断胜负。

## 信息与权限

所有玩家可以看到：

- 当前阶段、轮次、截止时间和 speaker。
- 房间席位的准备、在线和存活状态。
- 已公开死亡、已结算票型和最终胜负。

本人额外看到：

- 自己的角色、阵营、技能余量和可执行动作。
- 自己在当前阶段最后提交的目标或弃权状态。
- 预言家本人的查验结果。
- 女巫行动阶段规则允许公开给女巫的当夜袭击目标。

存活狼人可以看到狼队友。普通出局玩家和观战视图不会自动获得完整身份；全部身份只在游戏结束后公开。

## 实时原声

实时原声使用浏览器原生 WebRTC：

- 当前 speaker 单向发送音轨，最多连接八名接收者。
- 应用服务只处理同源信令，不代理或保存 RTP 音频。
- 非当前 speaker 的本地音轨会停止。
- 玩家必须主动开启实时原声后，浏览器才会请求麦克风权限。
- 可选 `ICE_SERVERS` 支持自管 STUN/TURN。

没有 TURN 时，复杂 NAT 或企业网络中的 P2P 连接可能失败。实时连接状态不能替代内容片段；玩家仍可使用按段录音作为发言和复盘的降级路径。

## 声证片段

声证是绑定牌局、阶段和 speaker 的原声片段。它包含：

- 不透明 `segmentId`。
- `gameId`、`phaseKey` 和 `speakerSeatId`。
- 内容类型、字节大小、录音时长和创建/过期时间。
- 原始音频的 SHA-256。
- 灵汐转写状态及成功时的文本。
- 当前查看者自己的私人标记。

SHA-256 能证明回放字节与服务端记录的摘要一致，防止引用和文件被无声替换。它不能证明说话人的现实身份、内容是否真实、录音是否经过表演，也不是第三方数字证书。界面在缺少摘要时显示“未验证”，摘要不一致时阻止播放。

### 留存

- 原声默认进入有界临时存储，用于当前牌局播放和转写。
- 玩家必须显式开启“赛后保留”，片段才进入持久化声证引用与赛后复盘。
- 当前默认 TTL 为 2 小时；显式保留也不是永久归档。
- 未保留片段在游戏结束后不进入复盘。
- 原声、转写和标记都按座位令牌鉴权，不使用公开 URL。

### 私人标记

玩家可以给自己有权查看的片段添加简短标记，例如“关键发言”或“票型矛盾”。标记只属于创建者，不会变成系统对玩家或发言的事实判断。相同声证的标记不能被同一幂等身份静默改写。

## 灵汐能力

所有语音智能能力只使用灵汐 API：

- `gpt-4o-transcribe`：片段转写。
- `gpt-4o-mini-tts`：固定阶段主持音。

灵汐不参与角色分配、死亡结算、投票或胜负判定。健康状态区分 `implemented`、`checked` 和 `healthy`；未执行真实检查时不会显示为在线。

未配置或调用失败时：

- 原声录制和鉴权回放仍可用。
- 字幕明确显示失败或不可用，不生成模拟转写。
- 主持音退化为同内容文字。
- 牌局规则和计时继续由服务端状态机推进。

## 事实复盘

赛后复盘由结构化事实直接生成，不调用 LLM，也不生成推理结论。复盘包含：

- 最终胜方与公开角色。
- 每轮公开票型。
- 死亡席位、轮次与公开原因。
- 玩家选择保留且仍在 TTL 内的声证。
- 当前查看者自己的声证标记。
- 指向上述票型、死亡和声证 ID 的模板化转折点。

“可验证”表示每个转折点必须引用复盘中真实存在的结构化记录，声证文件必须匹配 SHA-256。它不表示系统知道哪名玩家说了真话，也不表示转折点具有唯一解释。

## 失败与恢复

| 场景 | 产品行为 |
| --- | --- |
| 麦克风权限拒绝 | 不采集音频，保留文字阶段提示和规则动作。 |
| P2P 连接失败 | 显示未连接，允许使用片段录音降级。 |
| 灵汐未配置或异常 | 保留原声；字幕失败；主持音使用文字。 |
| 玩家断线 | 保留席位和私密身份，凭原 seat token 重连。 |
| 可见版本冲突 | 丢弃本地过期选择，重新获取本人最新快照。 |
| 服务重启 | 从 SQLite 恢复房间和事件；所有席位先标记断线。 |
| 媒体文件缺失或摘要不符 | 不把片段标为已验证；摘要不符时阻止播放。 |

## 架构摘要

```text
Chrome Web 客户端
  |-- HTTPS / SSE / JSON ----------> Node.js 24 模块化单体
  |                                   |-- Room + 确定性规则引擎
  |                                   |-- 玩家级快照投影
  |                                   |-- SQLite v1 持久化
  |                                   |-- 声证索引与本地媒体目录
  |                                   +-- 灵汐 STT / TTS 网关
  |
  +-- WebRTC P2P 原声音轨 ----------> 当前房间其他浏览器
          同源服务仅转发信令，可选自管 TURN relay
```

SQLite 是当前单实例产品的实际选择，不是 PostgreSQL 的兼容层。未来如果需要横向扩展，必须重新设计房间所有权、事件并发、共享媒体、信令和数据库迁移，不能只替换连接字符串。

## 数据与安全说明

- Seat token 只保存在当前浏览器标签页的 `sessionStorage`，通过 Bearer header 发送，不进入 URL。
- 灵汐密钥只存在于服务端环境变量。TURN 配置由服务端读取，仅向已鉴权的房间参与者下发；浏览器需要该配置建连，部署时应使用受限凭证。
- SSE 使用不透明 viewer cursor，不公开权威事件序号。
- 服务端按玩家生成快照，不依赖 CSS 隐藏秘密字段。
- SQLite 和备份属于敏感数据，可能包含未结束房间凭证、转写和私人标记。
- 当前没有账号体系、端到端加密、内容审核或永久合规归档能力。

## 待验证假设

以下内容是需要真人试玩验证的假设，不是研究结论：

- 9 人通过房间标识可以在一分钟内完成组局。
- 实时原声加按段声证比纯语音更利于复盘争议。
- 私人标记能帮助玩家组织推理，但不会明显增加操作负担。
- 结构化事实复盘能促进“再来一局”，而不需要 AI 自动点评。

验收应记录真实完局率、组局耗时、断线恢复、P2P/TURN 成功率、片段上传成功率和复盘回听率。未进行真实用户研究前，不据此宣称市场验证或用户偏好。
