# 原声、声证与恢复

H3/H4 接入真实原声片段、灵汐字幕/主持音、私密标记、事实复盘与 SQLite 持久化。正式入口 `npm start` 使用 `src/runtime`，默认数据文件 data/wuyin.sqlite；不再启动演示牌局。

## 语音与灵汐

- 只有当前在线发言者在白天或遗言阶段可上传。完整接收请求体后重新校验阶段实例、发言者和截止时间，防止慢上传越阶段。
- 原声存储与字幕独立。灵汐未配置、超时、限流或失败时保留合法原声并明确返回字幕失败，规则正常继续。
- STT 固定 gpt-4o-transcribe，TTS 固定 gpt-4o-mini-tts；只访问灵汐 api.aicso.top。输入、输出、时间、并发和各房间/席位配额有界。
- 状态分开报告 configured、implemented、checked 和 healthy，没有真实调用前不会显示已验证在线。
- 主持文字由服务器阶段生成，TTS 按阶段缓存并共享并发请求；播放失败保留文字。

## 声证特色

片段返回 SHA256，客户端回听前验证实际字节。SHA256 证明内容完整性，不证明说话者诚实或现实身份。

标记只能引用真实且本人有权限读取的片段；本人标记对其他玩家不可见。结束后根据公开身份、票型、死亡和授权语音生成事实复盘，每条转折引用真实记录。当前是确定性事实复盘，不冒充 LLM 分析或虚构证据。

玩家可以向房主提交本地房间举报，只有当前房主能查看；每人每局最多 10 条。不自动封禁、不向外部平台发送举报。

## 隐私与持久化

- 原声默认临时保存，赛后不保留；需要回听证据时由玩家明确开启 retain。
- 显式保留片段写入受控本地媒体目录，0700 目录、0600 文件，内容寻址并校验。默认保留期限两小时，不是无限存档。
- SQLite 原子保存牌局与幂等数据。保留片段引用、私密标记和删除记录可恢复，原始音频不进入数据库或 GitHub。
- 删除记录会在重启后继续清理；同一 SHA 多引用时只在没有其他有效引用后删除文件。过期片段不能因相同字节的新片段复活。
- 持久化提交失败时回退内存房间状态。恢复后所有座位先置离线，原令牌重连恢复本人状态。进程恢复与网络重连分别测试。

SQLite 是本版本可独立运行的单实例方案，替代原计划需要外部服务的 PostgreSQL 优先方案；没有承诺多副本并发写入或横向扩容。数据库和媒体需要配套备份，schema v1 不支持任意降级。

## 接口

| 路径 | 方法 | 功能 |
| --- | --- | --- |
| /api/lingxi/status | GET | 能力与真实健康检查状态 |
| /api/rooms/:id/voice | POST | multipart file、durationMs、可选 retain=true |
| /api/rooms/:id/voice | GET | 当前玩家可读取的片段列表 |
| /api/rooms/:id/voice/:segmentId | GET | 经座位鉴权的原声字节 |
| /api/rooms/:id/voice/:segmentId/mark | POST | 私密证据标记 |
| /api/rooms/:id/voice/:segmentId/remove | POST | 本人的删除请求 |
| /api/rooms/:id/narration | POST | 当前阶段的灵汐主持音 |
| /api/rooms/:id/recap | GET | 结束后的引用可验证事实复盘 |
| /api/rooms/:id/reports | POST / GET | 玩家举报 / 当前房主查看 |

本功能使用原声分段降级链路；低延迟 WebRTC 与 TURN 在独立 PR 中接入。不使用字幕成功来代替原声互听验收。
